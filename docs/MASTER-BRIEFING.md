# ABMSOL — MASTER BRIEFING
## Evolução de experiência digital, engenharia de interfaces e desenvolvimento web avançado

**Projeto:** ABMSOL — Tecnologia, desenvolvimento e suporte de TI
**Objetivo:** Transformar o site existente em uma demonstração de excelência em desenvolvimento web, engenharia de interfaces, experiências interativas e design digital contemporâneo.

---

# 1. VISÃO GERAL DO PROJETO

Quero elevar o nível técnico e visual do site da ABMSOL.

O objetivo não é simplesmente modernizar o layout, adicionar animações ou reproduzir referências do Awwwards.

Quero desenvolver uma experiência digital que demonstre domínio de desenvolvimento web profissional, criatividade técnica, capacidade de resolver problemas complexos de interface e conhecimento de tecnologias modernas.

O próprio site deve ser uma demonstração da qualidade do trabalho que a ABMSOL é capaz de entregar.

A experiência precisa transmitir três características fundamentais:

1. **Excelência visual:** uma identidade digital sofisticada, contemporânea e reconhecível.
2. **Excelência técnica:** código bem estruturado, interações avançadas, arquitetura consistente e tecnologias utilizadas com propósito.
3. **Excelência comercial:** uma experiência que transmita confiança, apresente os serviços com clareza e transforme visitantes em potenciais clientes.

O projeto deve combinar referências de qualidade visual do Awwwards com os princípios de engenharia de interfaces utilizados por estúdios digitais de alto nível.

Não quero um template de agência, um site genérico de tecnologia ou uma coleção de efeitos visuais desconectados.

Quero uma experiência própria da ABMSOL.

# 2. DIRETRIZES FUNDAMENTAIS

Antes de qualquer implementação, respeite estas diretrizes:

- Não reconstruir o projeto do zero sem uma justificativa técnica.
- Não remover funcionalidades existentes sem avaliar seu impacto.
- Não descaracterizar a identidade visual da marca.
- Não instalar bibliotecas apenas para adicionar efeitos.
- Não utilizar animações genéricas sem propósito.
- Não sacrificar performance em troca de efeitos visuais.
- Não criar funcionalidades fictícias.
- Não inventar depoimentos, clientes, resultados, métricas ou cases.
- Não utilizar placeholders como se fossem projetos reais.
- Não prejudicar SEO, acessibilidade ou responsividade.
- Não alterar textos comerciais sem necessidade ou sem preservar seu significado.

Toda implementação deve ter uma justificativa visual, técnica ou funcional.

A qualidade deve prevalecer sobre a quantidade de recursos.

# 6. SISTEMA DE MOTION DESIGN

Quero que o site tenha um sistema consistente de animações, não efeitos independentes espalhados pelos componentes.

Avalie a implementação de GSAP e ScrollTrigger, considerando a arquitetura existente.

Crie padrões reutilizáveis para:

- Entrada de elementos.
- Revelação de títulos.
- Stagger de listas.
- Animações de cards.
- Transições de seção.
- Elementos vinculados ao scroll.
- Animações de SVG.
- Microinterações.
- Estados de hover.
- Transições entre páginas, se houver múltiplas rotas.

## Regras de motion design

- Utilizar transform e opacity sempre que possível.
- Evitar animações constantes que disputem atenção.
- Evitar efeitos que provoquem mudanças bruscas de layout.
- Não animar elementos que não precisam ser animados.
- Garantir que o conteúdo continue acessível sem animações.
- Respeitar prefers-reduced-motion.
- Evitar conflitos entre GSAP e outras bibliotecas de animação.
- Limpar corretamente timelines, listeners e ScrollTriggers quando componentes forem desmontados.

Crie uma linguagem de movimento consistente.

O visitante deve perceber continuidade entre as seções.

# 17. PERFORMANCE E OTIMIZAÇÃO

A experiência visual não pode comprometer a performance.

Estabeleça metas de qualidade:

## Lighthouse

Buscar, em produção ou ambiente equivalente:

- Performance: 90 ou mais.
- Accessibility: 95 ou mais.
- Best Practices: 95 ou mais.
- SEO: 95 ou mais.

Esses valores são metas, não justificativa para manipular medições ou remover funcionalidades importantes.

## Core Web Vitals

Buscar:
- LCP até 2,5 segundos.
- INP até 200 ms.
- CLS até 0,1.

## Otimizações

- Imagens em formatos modernos.
- Dimensões explícitas de imagens.
- Lazy loading para conteúdo fora da primeira dobra.
- Priorização adequada do conteúdo principal.
- Fontes otimizadas.
- Preload apenas dos recursos realmente críticos.
- Code splitting.
- Carregamento sob demanda.
- Redução de JavaScript desnecessário.
- Evitar bibliotecas redundantes.
- Otimização de animações.
- Evitar processamento contínuo sem necessidade.

Não carregue Three.js, modelos 3D ou recursos pesados antes de serem necessários.

Meça antes e depois das principais alterações.

# 26. GERENCIAMENTO DE CONTEÚDO E PLACEHOLDERS

Um requisito importante: quero que o site fique tecnicamente pronto mesmo sem todos os textos e imagens definitivos.

Não quero precisar reconstruir as páginas quando fornecer os materiais reais.

Centralize os dados de apresentação pessoal e projetos.

Se a stack permitir, utilize uma estrutura tipada.

Exemplo conceitual:

```ts
type Project = {
  id: string;
  slug: string;
  title: string;
  category: string;
  description: string;
  coverImage?: string;
  gallery?: string[];
  technologies?: string[];
  year?: string;
  client?: string;
  challenge?: string;
  solution?: string;
  process?: string;
  results?: string;
  featured?: boolean;
  published: boolean;
  isPlaceholder?: boolean;
};
```

Crie uma estrutura semelhante para o perfil profissional.

Os dados devem ficar separados dos componentes visuais.

## Regras dos placeholders

- Utilizar identificadores explícitos.
- Permitir substituição simples.
- Não apresentar textos provisórios como informações verdadeiras.
- Não exibir imagens fictícias como projetos reais.
- Não mostrar campos sem conteúdo.
- Permitir desativar placeholders em produção.
- Garantir que o site continue visualmente consistente sem conteúdo opcional.

Se possível, utilize uma configuração central para controlar a exibição de conteúdos demonstrativos.
